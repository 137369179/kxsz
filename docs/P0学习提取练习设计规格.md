## 0. 代码深研结论（打磨依据）

对照 `ReviewModule` / `flashcardEngine` / `morphEngine` / `etymologyQuiz` / `cardHub` / `reviewConfused` 后的硬事实：

| # | 发现 | 对方案的影响 |
|---|------|----------------|
| A | `ReviewModule` **已 import** `buildAtomicCardsForChar` / `recordAtomicAnswer` / `ATOMIC_CARD_TYPES`，但 `renderRound` **只挂 `DrillEngine`**，原子卡 UI 零调用 | 建议 1 不是「从零发明」，是**把已接线的数据层接上 UI** |
| B | Drill 结束时对 **全部 5 种**原子卡执行 `recordAtomicAnswer(..., perfect)`（同一布尔） | **诚实性缺陷**：一张 MC 结果污染五维 atomicStats，导致 `isCardMastered` / 队列过滤失真。自由提取落地应**顺带改为按卡种记账** |
| C | 复习顶栏多模态条在答题前展示部首 /「别搞混」/ 口诀 | 直接破坏测试效应；自由提取模式下 **prompt 阶段必须隐藏**（reveal 后再显示） |
| D | `flashcardEngine` 明确「纯数据、零 DOM」；`CardModule` 闪卡是浏览翻面，无 FSRS、无「先说再翻」 | UI 应新建 `reviewHub/freeRecallView`，**不要**改造字卡浏览幻灯 |
| E | `CHAR_TO_WORD` 读 `char.words`，而组词在 `CHARACTER_DETAILS`；Review 队列来自 `CHARACTER_DATABASE` **未 merge details** | MVP **不要**依赖组词卡；仅用 `CHAR_TO_PINYIN` / ≤4 用听音选字。组词卡留到 hydrate 后再开 |
| F | 空队列回退会 `CHARACTER_DATABASE.slice(0, wantRev)`，可能复习**未学字** | 自由提取队列必须 **仅已学字**；无已学则走空态，禁止用字库前 N 字凑数 |
| G | 全库 1489 字均有 `confusingChars` + `confusingHint`；Stage1 双向互指仅约 42 条有向边 | 入包门控改为「目标已学 + 至少一个已学干扰项」，**不要求**双向互列；优先 `errorProfiles` 对 |
| H | `confusedTargetsForReview` 只读 errorProfiles，与字段 `confusingChars` 是两条线 | 交错包构建函数应 **双源合并**：错题对优先，再补 confusingChars |
| I | `openMorphTheater` **无 onClose**；morph 为可选按钮；认字结束强制 `openEtymologyQuiz`（有对错） | 自我解释挂 **close 回调**；与 quiz **互斥或二选一**，避免 morph+解释+quiz 三连疲劳 |
| J | `planDailySession` 仍无 UI 调用 | 交错包自建轻量交错即可，**不必**先复活完整 sessionPlanner |

### 修订后的默认决策（覆盖原稿开放问题）

1. 复习 MVP：**以自由提取为主路径**（替换当前 Drill 主路径）；Drill 降为总结页「还想玩游戏练」可选，避免双倍时长与双重记账。  
2. 自我解释：**不录音**；「我说了」+ 联想芯片。  
3. 交错包：复习队列自由提取**全部跑完后**追加一包（有合格对才出）。  
4. **新增**：落地建议 1 时必须修复「五卡同写」诚实性（按单卡种 `recordAtomicAnswer`）。

## 1. 目标与非目标

### 目标

把复习与认字路径从「再认主导」补上三条高杠杆提取/生成练习，并修正原子卡统计失真：

1. **自由提取闪卡**（测试效应）+ **按卡种诚实记账**
2. **形近字交错练习包**（交错练习）
3. **字源后自我解释**（生成效应）

### 非目标（本规格明确不做）

- 不改造 Learn Step8「测」（该步是结业庆祝，不是测验）
- 不重写 FSRS 闭式间隔主路径
- 不新增字库字段（复用 `confusingChars` / 现有 details）
- 不实现摄像头具身识字、绘本随文识字
- 不把每日上限门禁页改造成睡前庆祝页
- 不改造 `CardModule` 浏览闪卡为复习引擎
- MVP 不启用 `CHAR_TO_WORD` / `CHAR_TO_STROKES` / `CHAR_TO_RADICAL`（缺 hydrate 或非核心提取）

### 诚实性红线（三项共用）

- 自我解释**永不评判对错**、不扣星、不记「错误」
- 自由提取说错 → 温和再试或示范，**禁止羞辱文案**；「遗忘警报」横幅改为中性「再练一次」（避免恐吓感；MVP 至少禁止人格否定）
- 交错练习可提示「有点难是正常的」，禁止「你记性差」类归因
- 全走 `ebbinghausManager.getAge()` 年龄门
- **禁止**再用单次 Drill/`perfect` 批量写满 5 种 `atomicStats`

## 2. 建议 1：自由提取闪卡

### 2.1 用户故事

> 作为复习中的孩子，我先看到汉字，自己想起读音，再点「我会了」翻开答案核对；而不是一上来就四选一，更不是顶栏已经把口诀和易混字剧透了。

### 2.2 年龄行为

| 年龄 | 模式 | 交互 |
|------|------|------|
| ≤4 | **指认降级** | 听读音 → 点选正确汉字（可用轻量 2–4 选项；属 recognition，符合年龄） |
| ≥5 | **自由提取（读音）** | 见字 → 点「我会读」→ 翻开拼音 → 点「对了」/「再听听」 |

≥7 的组词卡：**延后**（待 Review 合并 `CHARACTER_DETAILS` 后再开）。

### 2.3 状态机（单卡，≥5）

```text
[prompt] 仅大字 +「先自己读出来」；无拼音、无易混条、无口诀条
    │ 点「我会了」
    ▼
[reveal] 拼音 + 可选一句义；可点喇叭听示范
    │ 「对了」 → recordAtomicAnswer(CHAR_TO_PINYIN, true)  → completeReview(GOOD/EASY)
    │ 「还不会」→ TTS 示范 → recordAtomicAnswer(..., false) → completeReview(HARD/AGAIN)
    ▼
[next]
```

≤4：`SOUND_TO_CHAR` 流程（听 → 选字），用 `checkCardAnswer`；对/错同样只记 **该卡种**。

### 2.4 与现有代码的挂接

| 层 | 复用 | 改动 |
|----|------|------|
| 数据 | `flashcardEngine` 现有类型与 `recordAtomicAnswer` | 可选 `pickRecallCard(char, age)` 纯函数 |
| UI | 新建 `src/utils/reviewHub/freeRecallView.js` | `ReviewModule.renderRound` 主路径改挂此视图 |
| 调度 | `completeReview(charId, rating)` | 继续传 age（已接线） |
| 诚实性 | — | **删除**「for 全部 ATOMIC_CARD_TYPES 写同一 perfect」循环 |
| 队列 | `initQueue` | 过滤未学字；禁止 `CHARACTER_DATABASE.slice` 凑数；空则 `renderEmpty` |
| 预览条 | 多模态条 | free-recall 的 prompt 阶段不渲染；reveal 后可选 |

### 2.5 会话策略（MVP，已拍板）

- 主路径：**每字 1 张** `CHAR_TO_PINYIN`（≤4 为听音选字）
- Drill：**移出主路径**；可在 `renderSummary` 提供「小游戏加练」入口（可选，非必须首 PR）
- 连续「还不会」仍可把该字 append 到队尾（保留现 SM-18 重练意图，文案中性化）

### 2.6 验收标准

- [ ] ≥5：reveal 前 DOM/可见文案无拼音、无易混剧透条
- [ ] 只更新对应 `atomicStats` 字段，不再五卡同写
- [ ] 「还不会」不扣人格评价、不出现辱骂文案
- [ ] 队列无未学字凑数
- [ ] 单测：年龄门、单卡记账、rating 映射；可选 CDP 翻卡顺序

## 3. 建议 2：形近字交错练习包

### 3.1 用户故事

> 我已经学过「日」和「目」。复习读音都做完后，来一包「找不同」：同屏几个很像的字，帮我分清它们。

### 3.2 入包门控（修订）

生成一道题的条件：

1. 目标字 `T` ∈ 已学；
2. 干扰项中至少 1 个 ∈ 已学，且来自 `T.confusingChars` **或** `errorProfiles.confusedPairs[T]`；
3. 其余槽位可用未学形近字填充（仅作选项，不当「双侧必学对」）。

**不要求** `T`↔`U` 在彼此的 `confusingChars` 里互列（Stage1 互指稀疏）。

优先级：errorProfiles 高频对 > 当前复习队列字的 confusingChars > 其它已学字的 confusingChars。

### 3.3 玩法（MVP）

```text
题面：「找出：目」+ 3–4 选项（含形近）
反馈：对 → 短正向；错 → 展示 confusingHint（全库已有）
节奏：4–6 题；目标字在包内至少切换 2 次（交错）
```

质量备注：部分 `confusingChars` 语义偏弱（如水→木/小/米）。MVP **信任现有字段**；P1 再加「同部首 / 编辑距离」过滤。不因此阻塞 P0。

### 3.4 挂接

| 层 | 复用 | 改动 |
|----|------|------|
| 解析 | `resolveCharRef` / errorProfiles / `confusingChars`/`confusingHint` | 新建 `reviewHub/interleavePack.js`：`buildInterleavePack({ learnedIds, dueIds, errorProfiles, limit })` |
| UI | — | `interleaveView.js`；由 Review 在自由提取结束后 `renderInterleave` |
| 调度 | `completeReview`；错可 `recordMistake('similar_confuse')` | 与现有错题画像一致 |

### 3.5 验收标准

- [ ] 无「双侧都未学」的必辨对
- [ ] 包内目标至少切换 2 次
- [ ] 有 `confusingHint` 时错答可见
- [ ] 单测：双源合并 + 门控 + 交错度

## 4. 建议 3：字源后自我解释

### 4.1 用户故事

> 我看完象形剧场关上后，凯茜问「你觉得这个字像什么？」；我说什么都算棒，也可以跳过。

### 4.2 与 etymologyQuiz 的关系（修订）

| 方案 | 说明 | 推荐 |
|------|------|------|
| A. 自我解释替换认字结束的强制 quiz | 减少有对错压力，贴近生成效应 | **MVP 推荐（≥5）** |
| B. morph 关闭后解释，结束仍 quiz | 三连疲劳 | 否 |
| C. 仅 morph 关闭后解释，结束保持 quiz | morph 可选 → 解释覆盖率低 | 否作唯一路径 |

**MVP**：`getAge() ≥ 5` 时，认字步结束按钮触发 **自我解释**（可跳过），**不再强制** `openEtymologyQuiz`；≤4 保持现有 quiz 或直接进入下一步（与现网一致即可）。

morph 仍可选；若打开 morph，关闭时若本步尚未做过自我解释，可先弹解释（同一会话防抖 `_selfExplainDone`）。

### 4.3 交互（MVP）

- 问句 TTS + 3 联想芯片（从 `oracleDesc` / `mnemonic` 截词 + 1 通用兜底）+「我说了！」+「跳过」
- 任意完成 → 正向回应 → `onDone`
- 不写 errorProfiles、不 completeReview 记错

### 4.4 挂接

| 层 | 改动 |
|----|------|
| `morphEngine.openMorphTheater(char, container, { onClose })` | close() 末尾调 onClose |
| `learnSteps/selfExplainPrompt.js` | UI |
| `stepRecognize` 结束按钮 | ≥5 → selfExplain → 下一步；不再强制 quiz |

### 4.5 验收标准

- [ ] ≤4 不出现自我解释层（或与现网 quiz 策略一致且单测锁定）
- [ ] ≥5 可跳过；无惩罚
- [ ] 无「不对」文案；不写 mistake
- [ ] morph `onClose` 有单测或最小集成断言
